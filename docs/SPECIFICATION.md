# 产品与工程约定

版本：规划基线 v2，2026-11-14；**2026-11-15 修订**——§2 模块边界按实际实现更正，§4 新增可返航范围契约，§5 新增时间轴回看语义，§6 新增改版计算预算（视觉改版 V1–V4，见 [实施计划](IMPLEMENTATION.md) §7）。阶段状态见 [实施计划](IMPLEMENTATION.md)，事实来源见 [调研](RESEARCH.md)。

## 1. 用户、任务与范围

产品面向希望理解火星出舱探索决策的参赛评委、学生与公众，以任务控制台呈现。界面和对外材料默认英文，开发规划中文。不是实际飞行任务的认证软件。

主故事：从一个模拟基地出发，到有科学依据的目标进行观察或采样，在预算内返回；发生电池损失或路线阻断时，展示如何重新决策。

| 范围 | 约定 |
| --- | --- |
| 核心版本 | 一个 Jezero 区域、至少 3 个科学地点可供选择、每次一个目标、去程和返程、资源估计、任务播放、两类事件、来源面板 |
| 首版地图 | 以 DEM 驱动的立体地形沙盘为首要视觉目标，叠加贴地路线和地点；二维底图作为核对与回退视图 |
| 视觉方向 | 电影感火星探索：峡谷光影、基地/人物比例参照、少量边缘任务面板；状态同时用文字/图形表达 |
| 立体与动效 | 阶段 3 验证可旋转地形及选点转场，阶段 4 增加人物移动和事件镜头；生成概念图不是可用模型，实时效果需性能验证 |
| 增强功能 | 多目标、MEDA 历史曲线、辐射模型、AI 自然语言解释；按扩展验收执行 |
| 不纳入本轮 | 全球火星导航、账户系统、多人同步、真实宇航服控制、实时火星气象预测、无证据的精确生命安全结论 |

## 2. 架构选择

默认采用 **React + TypeScript + Vite** 管理交互，**WebGL 地形视图 + SVG/HTML 控件** 呈现沙盘，Canvas 2D 保留为核对与回退视图，CSS 变量维护视觉主题。包管理使用 npm 和锁文件；阶段 2 检查已有 Node 环境后选择兼容稳定版本并记录，不在规划中锁定未经检查的版本。

地图使用本地米制平面坐标。第一版不引入默认采用地球 Web Mercator 的底图服务，不自研通用 GIS 或三维引擎。阶段 3 先验证成熟渲染库与现有环境的适配，再冻结具体选型；不能用整张生成图片代替可交互地形通过验收。应用产物为静态文件，核心演示无需 NASA API、AI API 或密钥。完成首次资源加载后，核心操作不依赖外部请求；这不等同于承诺首次离线打开或完整 PWA。

数据预处理优先使用已有 Python/地理处理环境；若没有合适环境，先评估轻量解析方式或已有云端工具。不能为了处理一个文件擅自安装大型 GIS/容器环境。阶段 1 记录实际使用工具、版本和命令。

实际模块边界（2026-11-15 按已实现更正；原"计划模块边界"与实际不符）：

```text
scripts/data/            获取、裁剪、变换与验证（Python，阶段 1 已交付）
scripts/validate-data.ts 数据校验 CLI（npm run validate:data）
public/data/jezero/      可发布数据包与来源 manifest（schemaVersion 1.1）
src/domain/          types 契约、assumptions 参数范围、load 解析校验、
                     world 显示映射（坐标/双线性采样/相机取景，垂直×4.5 仅显示）
src/routing/         graph 通行性与边代价、search A*/Dijkstra、budget 预算、plan 往返编排
src/simulation/      engine 确定性状态机（missionStateAt / planEmergencyReturn）、
                     runtime、presets 脚本化场景
src/data/            Node 与 fetch 两种加载适配器（共用纯解析核心）
src/ui/              App 外壳、Sandbox（R3F 沙盘）、panels、PlanView2D、
                     HudStrip、MissionLayer、cameraBus、i18n、主题 CSS
src/cli/             demo CLI（npm run demo）
未创建：src/map（坐标职责并入 domain/world）、src/components（并入 src/ui）、
        src/workers（主线程实测无阻塞，未引入）
```

后续新增（视觉改版 V2/V3）：时间轴组件并入 `src/ui/`，反向 Dijkstra 成本场并入 `src/routing/`（`costFieldToBase`），不新建顶层目录。

应用显示值全部从计算结果派生，组件不能另写一套资源公式。前期不为性能假设增加 Worker；需要时用请求 ID 丢弃旧结果，禁止旧路线覆盖新事件状态。

## 3. 数据契约

所有资产带 `schemaVersion`，加载时校验；缺失/不合法数据显式报错，不能默默换成随机样例。

| 实体 | 必需字段或规则 |
| --- | --- |
| SourceRecord | `id, mission, instrument, title, sourceUrl, productId, retrievedAt, observationTime, units, credit, usageTerms, limitations`；未知值写 null 并说明，不捏造 |
| Provenance | `kind: observed / derived / simulated`、`sourceIds`；派生项增加 `method, parameters, inputHashes`；模拟项增加 `assumptionIds` |
| Region | `id, name, boundsLocalM, projection, horizontalDatum, verticalDatum, transform, sourceIds`；保留原始投影与处理后的本地坐标定义 |
| TerrainGrid | `width, height, originXM, originYM, cellSizeM, elevationsM, validMask, slopeDeg`；数组为行优先，首行北侧，列向东，行向南；NoData 用独立 mask，不能编码成 0 高程 |
| ScienceSite | `id, name, xM, yM, objective, sourceIds, imageIds, positionUncertaintyM, samplingDurationMin`；停留时间为模拟参数；图片相机位置与目标位置分开 |
| Scenario | `id, base, availableSiteIds, initialResources, reserveFractions, movementParameters, eventDefinitions, assumptionIds`；基地、事件和宇航服均为模拟 |
| RouteRequest | 区域/数据版本、起点、目标、策略、阻断掩码、资源、参数版本、请求 ID |
| RouteResult | `status: feasible / over_budget / unreachable / invalid_input`，路线分段、距离、时间、各资源消耗、余量、原因码、输入版本；无路线时不返回假路径 |
| SimulationState | 状态、模拟时刻、当前位置、剩余资源、任务/路线版本、已应用事件 ID、已完成停留时间 |

所有内部长度为米、时间为分钟、角度为度；氧气与电池先用各自独立的 0–100 模拟预算单位，不显示为实测升数、Wh 或生理模型。后续使用物理单位需要证据与换算约定，不能只换标签。

### 空间与时间处理

- 本地坐标 `x` 向东、`y` 向北，地图像素坐标向下时显式反转。网格原点为左上角外边界；格心为 `originX+(col+0.5)*cellSize`、`originY-(row+0.5)*cellSize`。
- 从源投影转换到本地米制坐标；地理坐标转换必须使用相应火星参考体和纬度定义，禁止直接套用地球半径或把经纬度差当米。
- 保留源分辨率与规划分辨率。规划网格可更粗，不通过插值声称精度提升。重采样掩码与障碍采用保守规则；记录坡度在哪个分辨率上计算及聚合方法。
- 对齐检查至少 3 个分散控制点，项目验收目标为误差不超过一个规划格；若源资料本身达不到，就调整网格或显示不确定范围并说明。该阈值是工程验收约定，不是地理精度认证。
- UTC、sol 和模拟分钟分别存储。不同年代的地形与影像合用时展示各自日期；不伪装成同一时间切片。

## 4. 路线与资源模型

### 路径搜索

1. 在有效栅格上建立 8 邻接图，禁止斜向穿越两个障碍夹角。NoData、地图外、事件阻断区域以及超过配置坡度阈值的格子禁止通行。
2. 以米计算边长；坡度、爬升与额外行进时间可影响代价。坡度阈值是可配置情景参数，所有默认数值须在阶段 2 集中记录依据或标记假设。
3. 首版提供 `shortest` 与 `terrain-aware` 两种策略。后者使用非负额外代价；各量归一化后加权，不能直接把米、度和百分比混加。
4. 普通 A* 启发式使用最小单位距离代价乘直线距离，保持可采纳性；不用大于 1 的启发式倍率冒充严格最优。小图以 Dijkstra 结果核对。
5. 返程重新计算，不能简单反转去程；高程方向、事件和剩余资源可能不同。路线平滑仅为显示，不能穿障碍或更改用于预算的路径。
6. 起终点无效时返回原因；如允许吸附到格心，必须显示吸附距离并限制在一个格宽内，不能悄悄移动科学目标。

### 预算与可行性

边行进时间为距离 / 基础速度 × 坡度相关倍率；氧气和电池分别按行进时间消耗。停留、暂停任务中的科学操作与返程都计入模拟耗用；UI 的暂停播放冻结模拟时间，不额外扣资源。

对每类资源：

```text
计划总消耗 = 去程消耗 + 科学停留消耗 + 返程消耗
允许出发 = 初始资源 - 计划总消耗 >= 预留资源
预留资源 = 场景初始容量 × 配置预留比例
返航余量 = 当前资源 - 当前点至基地消耗 - 预留资源
```

预留量不随电池损失事件重新降低。20% 可作为场景初始配置，必须注明模拟假设。到达目标只代表完成路段，停留完成后才完成科学任务。

第一版搜索有限候选（两种策略），逐条检查预算。若候选均失败，显示“在当前策略下未找到满足预算的方案”，不证明所有可能路径均不可行；`unreachable` 专指图上空间不可达。不得宣称多资源全局最优。

### 可返航范围（returnable range，视觉改版 V3 契约）

在模拟时刻 T，格 c 属于可返航范围 ⇔：

```text
minTime(c → 基地) ≤ (剩余氧气(T) − 预留氧气) / 氧气率
且 minTime(c → 基地) ≤ (剩余电池(T) − 预留电池) / 电池率
```

- `minTime` 按 c→基地的**真实行进方向**以内核同款边模型（分钟代价）计费。边代价因爬升罚时按 `dz` 符号不对称，必须用自基地展开的**反向 Dijkstra**（松弛邻居时按邻居→当前方向计费，复用 MinHeap 与 edgeMetrics），不得用对称代价近似。
- 剩余资源必须取自 `missionStateAt(T)`（与界面显示同一数值来源）；封路掩码仅在该 T 已应用的封路事件生效。
- 宇航员当前格沿用应急返航的半边吸附约定；**当前格 ∈ 范围 ⇔ planEmergencyReturn（同位置、同资源）reachable 为真**，此项作为一致性验收断言。
- 范围回答"**此刻能否回家**"；中止策略（`firstReturnForcingEvent`）回答"还能否完成剩余任务并保留预留"。两者是不同的问题，界面上分别如实呈现，不得混用措辞，都不得渲染为绿色成功。
- 边界按 ±1–2 规划格的不确定度呈现（20 m 规划格 + CP2/CP3 对齐不确定度 22–26 m），标注 simulated，不是安全保证。
- v1 两种资源消耗率相等（各 100/480），判据退化为单一时间阈值；公式仍按资源独立书写，率分化时契约不变，仅需渲染层分别判定。

### 解释与可信度

首版用确定性原因码生成解释：坡度阻断、未知地形、预算不足、预留不足、事件封路、目标放弃。所有数字引用同一份 RouteResult。AI 助手不是核心路径依赖；未来只能解释有来源的结构化结果，不能修改路径、预算或生成不存在的数据。

## 5. 任务状态与事件

```text
idle → planned → running ↔ paused → completed
                       ↓
                   replanning → returning → completed
                       ↓
                  no_feasible_return
```

- 未通过预算检查不允许开始。修改目标、参数或数据后旧计划失效，需重新计算。
- 事件 1：电池损失（一次性扣减）；事件 2：指定区域封闭（路线失效）。都显式标为模拟，可单独触发并组合验证。
- 事件发生在模拟时刻，先冻结当前位置与资源，按事件 ID 应用一次，重新计算返回基地路线；不得把人物瞬移到起点或重置资源。
- 事件若发生在边中途，保留插值位置和已耗资源；从当前位置建立有效连接，剩余边与阻断区域相交时不得继续穿越。返回路径仍需从真实模拟位置开始。
- 默认应急策略为取消剩余科学任务并返航。无法满足预留但能到基地，与连到基地都无法完成要显示不同原因；都不能显示绿色可行状态。
- 无可行返回时停止正常任务播放，明确局限与失败原因，不捏造安全出口。重置恢复完整初始场景，清除事件和任务进度。
- 时间轴回看（视觉改版 V2）：`MissionState` 是模拟时刻 T 的纯函数（`missionStateAt`），拖动播放头到任意 T 即时派生该时刻的完整状态（位置、资源、阶段、事件日志），不需要历史缓冲。拖动即暂停；松手停留在拖到的 T；继续播放从该 T 起，E1 语义不变。
- 事件边界派生规则：仅当 T ≥ 事件触发时刻 t0 时传入已算好的应急计划（T < t0 传 null，显示名义状态）；向前拖动跨过尚未补算的 forcing 事件时，按 `firstReturnForcingEvent` + `planEmergencyReturn` 一次性补算并按事件 id 缓存（与运行时 forId 机制一致）。
- 时间轴是显示与回放控件，不是事件编辑器：事件只能经既定 schedule 触发（手动按钮或脚本预设），不得通过拖拽时间轴增改事件或时刻表。

## 6. 界面与性能约定

桌面主界面以地图为中心：任务设置、图层控制、科学点详情、去返程与预算摘要、状态 HUD、事件控制、来源与假设抽屉。预算信息不能只放在悬浮提示中。

必须覆盖加载、加载失败、空选择、计划可行、超预算、不可达、运行、暂停、重规划、返航、失败、完成。键盘可操作关键按钮；警告不只靠颜色；移动窄屏至少能阅读任务、滚动和触发关键操作，不要求完整头盔 HUD。

工程目标：正式数据包初次加载资源总量尽量控制在 15 MB 内；256×256 规划网格作为起始性能预算，必要时分层或缩小区域；目标机器记录浏览器与网格规模，单次规划交互目标 ≤1 秒，重规划不能长时间冻结界面。这些是待测目标。不能为了达标丢弃有效障碍或静默降低科学精度。

视觉改版新增计算预算（2026-11-15，待实测确认）：全图反向 Dijkstra 成本场单次重算 ≤50 ms（实测外推 ≤40 ms，256×256）；`missionStateAt` 单次派生为 O(路径长度)，拖动/播放帧率目标 ≥30 fps；边界等值线提取为 65k 格单遍扫描；重算触发一律节流（≥100 ms），不得逐帧重算。

## 7. 质量与交付

后续工程需提供类型检查、数据校验、算法单测、构建和关键浏览器旅程验证。命令名在阶段 2 落实为 `typecheck`、`validate:data`、`test`、`build`，浏览器测试按实际工具补充。

数据处理保存可复现命令、来源与校验和；大型原文件放任务缓存，不盲目提交 Git。提交裁剪资产前核对使用条款与体积。NASA 来源不自动代表所有第三方图像均可任意再分发。

发布以可公开访问的静态构建为目标，先检查现有托管能力再选 GitHub Pages 或已有平台；子路径资源、刷新与外部链接都要验证。不得在前端嵌入密钥。发布和提交遵循当时用户授权；技术验收不能替代正式提交回执。
